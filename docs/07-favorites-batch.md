# 收藏夹：返回位置修复 + 批量整理

## 一、修复：从收藏夹点进本子，返回后掉回默认收藏夹

### 根因

收藏页的「当前收藏夹 / 页码 / 排序」原本是**组件内部状态**，URL 里只有 `/home/favorites`。
点开本子时记录的返回地址是 `fromPath = ${pathname}${search}` —— search 是空的，所以**返回时导航回一个不带任何参数的地址**，页面重新挂载，三项状态全部复位成默认（默认收藏夹、第 1 页、按收藏时间）。

### 修法

把这三项放进 URL 查询串：

```
/home/favorites?folder=2&page=3&sort=mp
```

- 默认值不写进 URL（`folder=0`、`page=1`、`sort=mr` 会被删掉），地址栏保持干净
- 切换收藏夹或排序时页码自动回到第 1 页
- 变更用 `replace`，不往后退历史里塞垃圾条目
- 因为 `fromPath` 天然包含 `search`，**返回即还原**；前进/后退、刷新页面也都保持一致

顺带把**滚动位置**也记住了：以「收藏夹 + 排序 + 页码」为键存进 `sessionStorage`，返回时（列表通常能立刻从 SWR 缓存渲染出来）恢复。

> 这是搜索页当初用会话缓存解决的问题（`jm_search_state_v1`），收藏页此前没有做。放进 URL 比缓存更彻底：刷新、分享链接、后退都成立。

## 二、新增：收藏夹批量整理

入口在收藏列表右上角「**批量整理**」。

### 多选

- 进入批量模式后，每行/每张卡片出现勾选框；**点封面或标题即可选中**（此时不会跳转详情）
- 选中的条目带高亮描边
- 单条目的「阅读 / 取消收藏」按钮在批量模式下隐藏，避免误触

### 选择方式

| 按钮 | 行为 |
| --- | --- |
| 全选本页 | 选中当前页全部（已全选时变成「取消本页」） |
| 全选该收藏夹（所有页） | 逐页拉取该收藏夹的所有条目后全选 —— 处理几十上百条时不用一页页点 |
| 反选本页 | 本页已选与未选互换（保留其它页的选择） |
| 清空选择 | 清空全部选择 |

> 「全选该收藏夹」按总条数逐页请求，最多 100 页；页面会显示读取中的转圈。

### 批量操作

- **移动到收藏夹**：面板里列出所有收藏夹，点一个即开始移动；当前所在的收藏夹会标注「（当前）」并禁用；面板里也能直接**新建收藏夹**（新建后即可点选）
- **取消收藏**：把选中的本子一次性从收藏里移除

两者都显示「正在处理 n/N」，结束后给出成功/失败数量，失败时最多列 3 条明细（形如 `AID：错误信息`）。

### 实现说明

JM 的收藏夹接口**没有批量版本**（`/favorite_folder` 的 move 与 `/favorite` 的 toggle 都是针对单个本子），所以批量就是**逐条串行调用**：

- 串行而非并发：收藏这类写操作更容易触发风控，慢一点更稳，也让进度和失败归因更清楚
- 失败不影响其余条目，全部跑完再汇总
- 出现登录态失效时立即中止并触发重新登录

批量模式下「排序 / 收藏夹」两个下拉会暂时禁用 —— 否则选到一半列表被换掉，选择就失去意义了。

## 验证

`jm/e2e/app-ui.spec.ts` 新增 4 个用例：

1. **返回位置**：带 `?folder=2&page=2&sort=mp` 进入 → 点本子 → 返回后 URL 与下拉仍为收藏夹 2 / 第 2 页 / 更新时间排序，且最后一次 `api_favorites` 请求确实带上了 `folderId=2`、`page=2`
2. **批量移动**：多选 2 个 → 移动到指定收藏夹 → 断言 `api_favorite_folder_move` 的参数为这两个 AID 与目标收藏夹
3. **全选/反选 + 批量取消收藏**：断言 `api_favorite_toggle` 按选中顺序被调用
4. **跨页全选**：把收藏设为每页 2 条共 5 条，进入批量后「全选该收藏夹（所有页）」应选中 5 个，且分页请求为 1、1、2、3

全套 **36 个用例全绿**（`--workers=2`）。
