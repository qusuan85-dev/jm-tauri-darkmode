# 签到页面（每日打卡）

## 需求

加一个签到的界面：可以手动签到，并显示签到返回的经验和金币。

## 动手前的现状

后端命令**早就有了**，但没有任何界面：

| 命令 | 实际请求 | 之前谁在用 |
| --- | --- | --- |
| `api_daily` | `GET /daily?user_id=…` | 只有 App 启动时的自动打卡 |
| `api_daily_check` | `POST /daily_chk`（`user_id` + `daily_id`） | 同上 |

也就是说这次是纯前端工作，Rust 一行没改。

## 接口契约（按参考实现确认）

`GET /daily` 返回（移动端 API）：

```jsonc
{
  "daily_id": 72,                 // 当前签到活动 ID，签到时要带上
  "event_name": "9月-签到活动",
  "currentProgress": "14.3%",     // 连续进度
  "three_days_coin": "150", "three_days_exp": "150",
  "seven_days_coin": "350", "seven_days_exp": "350",
  "record": [                     // 按周分组的日历
    [ { "date": "01", "signed": false, "bonus": false }, … ]
  ]
}
```

网页端还会多返回 `error: "finished"`（今日已签到时）与 `oldStep`（连续天数），移动端不一定有 —— 所以两处都做了兼容。

`POST /daily_chk` 返回 **`{ "msg": "Jcoin:40 EXP:40" }`** —— **经验和金币就在这句话里**。

判定规则照抄参考实现：

- 成功：`msg` 含 `Jcoin` / `EXP` / `成功`，或 `status == "ok"`
- 今天已签：`msg` 含 `已簽到` / `已經簽到` / `簽到過` / `已完成` / `今天已經簽到過了`

## 界面

位置：侧边栏「签到」；手机端是底部导航的**第 6 个图标**（首页 / 阅读 / **签到** / 排行 / 搜索 / 设置）。

1. **今日状态**：`今天还没签到` / `今天已经签过到了，明天再来～`，并显示「连续进度 14.3%」；接口若返回连续天数也一并显示。
2. **立即签到**按钮：签到成功后直接给出奖励块 ——「**+40 金币**」「**+40 经验**」，数值从 `msg` 里解析（同时把服务端原文也显示出来，万一文案格式变了也看得到原始返回）。今天已签到时按钮变成「再签一次」，点击只会得到「今天已经签过到了」的提示，不会伪造奖励。
3. **连续奖励**：满 3 天 / 满 7 天的金币与经验一览（接口返回什么显示什么）。
4. **本月打卡日历**：按周排列，已签到=实心、未签到=灰底、未来=空白、今天带高亮圈，活动/双倍日带 ★。
5. **自动打卡开关**：从登录页移到这里（登录页少一个开关）。App 启动时的自动打卡逻辑没动，读的是同一个 `jm_auto_sign`。

## 测试

`jm/e2e/app-ui.spec.ts` 新增 4 个用例：

- 手动签到后显示 `+40 金币` / `+40 经验`，并断言调用 `api_daily_check` 时带上了正确的 `userId` 与 `daily_id`
- 今天已签到时给提示、且**不会**出现奖励块（并检查日历上今天那格标记为已签到）
- 自动打卡开关勾选后会写进 `localStorage`，刷新后仍是勾选；侧边栏「签到」能进入
- 手机端底部导航里有「签到」入口且可跳转

`e2e/support/tauriMock.ts` 相应补了 `api_daily` / `api_daily_check`，并按当月真实日期生成打卡日历，可用 `dailySignedToday` / `dailyCheckMessage` 控制两种分支。

## 需要真机确认的点

奖励文案解析按 `Jcoin:<数字> EXP:<数字>` 处理，并对全角冒号、空格、大小写做了容错。如果服务端的文案不是这个格式，界面依然会把**服务端原文**显示出来（「服务端返回：…」那一行），把那一行发我即可精确适配。
